01 / THE BIG IDEA

Same SEO work. Fewer moving parts.

Sanity is where you manage the website’s content. The website handles the design. You do not need to install plugins, edit code or rebuild the site to publish normal content changes.

▤

Pages

Edit the SEO settings, main heading, introduction and FAQs for existing website pages.

✎

Posts

Write articles, add images, choose an author and categories, then publish to the blog.

↗

Publish

Drafts save as you work. Publishing sends your approved content to the website.

The one rule to remember

Saved is not the same as published. Your live page keeps its previous content until you click Publish again.

  1. Open the editor.

    Visit www.truedgedigital.co.uk/admin. This is not WordPress’s /wp-admin address.

  2. Sign in with the account invited by the team.

    Choose the matching Google, GitHub or email login. You cannot sign in using an old WordPress username unless that email also has Sanity project access.

  3. Choose Website editor.

    If a tool selector is visible, choose Website editor. Developer tools is for technical work; you do not need it for everyday SEO.

04 / YOUR FIRST PAGE EDIT

Optimise an existing page.

Website editor › Pages › Web design › SEO settings
  1. Pick the correct page.

    For example, Web design edits /web-design. These are fixed website pages, so you do not need to create a new page record.

  2. Open SEO settings and write a unique title and description.

    Use the field guide below. You can leave individual fields empty to keep the website’s existing defaults.

  3. If needed, open Content.

    Page heading (H1) changes the large visible headline. Page introduction changes the supporting opening text. Keep both concise and check their appearance on mobile after publishing.

  4. Add or update FAQs if needed.

    Use complete questions and helpful answers. Read the replacement rule in section 06 first.

  5. Review, Publish, then open the live page.

    Confirm the text, page appearance and SEO metadata. You do not need to push code or deploy the website for these edits.

06 / FAQs

Answer the customer’s real questions.

Pages › choose a page › FAQs › add an item
  1. Add the question.

    Use a natural question a customer might ask. Example: “Can you redesign my existing website?”

  2. Write the complete answer.

    Be direct and accurate. Both the question and answer are required. These answer fields are plain text; do not paste HTML.

  3. Review the entire list, then Publish.

    Open the live page and check that the right FAQs appear. Matching FAQ structured data is produced automatically unless custom structured data overrides it.

A new FAQ list replaces the original list

If the website already has five FAQs and you publish one new item here, that one-item list becomes the page’s FAQ list. Add the full set you want visitors to see. An empty list restores/keeps original FAQs where the website has them; it is not a “hide all FAQs” switch.

FAQ structured data does not guarantee a rich result in Google. Use it to describe helpful content that is actually visible on the page.

07 / BLOG WORKFLOW

From a blank post to a published article.

WriteTitle, summary, image and body
→
OrganisePermalink, dates, author and topics
→
OptimiseSEO settings, review and Publish
  1. Open Posts and choose the create control.

    Choose Post if a type picker appears. For an existing article, open its record instead.

  2. Complete Post content.

    Post title (H1): the visible article heading.
    Excerpt (short summary): appears on the blog card and beneath the title.
    Featured image: add/select an image and describe it.
    Post body: write the article using paragraphs, headings and lists.

  3. Open Post settings and generate the permalink.

    Use Generate beside URL slug (permalink). A title such as “Local SEO for Salons” can use local-seo-for-salons. The resulting URL is https://www.truedgedigital.co.uk/blog/local-seo-for-salons. Review the generated slug before publishing.

  4. Check the publication time.

    For immediate publication, choose now or a past time. Confirm the date/time and time zone shown in your editor. A future publication date keeps the article off the website until that time AND a later cache refresh; it is not a precise scheduling service.

  5. Select an author and relevant categories.

    These are optional in the current form, but useful editorial information. Publish a new author/category first, then return and select it. Category names appear on cards and in the blog filters. Each category with a generated URL has its own archive at /blog/category/your-topic.

  6. Fill SEO settings if you want different search wording.

    Otherwise, the post title, excerpt and featured image provide the defaults. Keep the SEO title relevant to the article.

  7. Check all tabs and click Publish.

    The title, valid slug, publication date, excerpt, featured image with image description, and article body must be complete. Open /blog and the article URL to verify the result.

Authors

Open Authors → create an author. Add a name, optionally a role, bio and avatar. If you add an avatar, its image description is required. A slug can be generated from the name. Publish the author, then select it in the post.

Name/role appear with the article. Bio/avatar can appear in its author block. This does not create an author archive page.

Categories

Open Categories → create a topic. Add its name, generate the required Category URL and write a short introduction. Publish it, then select it under the post’s Categories field.

Its name appears in the filters. Its introduction appears on the category archive and provides its search description. Non-empty archives enter the sitemap automatically. Search, sorting and pagination are handled by the website.

Do not casually change a published permalink

Changing the slug changes the article URL. Sanity does not create a redirect here. Ask the technical team to redirect the old URL before changing a published slug.

Updating an old article? Open the existing post, edit it, and Publish again. Keep its original publication date. Use Last major update (optional) for a substantial revision; the website currently uses it for metadata and the sitemap rather than a separate visible “updated” label.
08 / YOUR CONTENT TOOLKIT

Readable articles, accessible images.

Headings

The post title is already the H1. Start the main sections with Heading 2. Use Heading 3 for subsections and Heading 4 only when another level is useful.

H1 · Local SEO for Salons
　H2 · Help nearby customers find you
　　H3 · Keep your business details accurate
　H2 · Make booking simple

Select text in the body and use its style menu. Bold text is not a substitute for a heading.

Images & alt text

Upload/select an image through Featured image or the body’s image insert control. Open the image’s details to fill Image description (alt text). A caption is optional.

Useful: “Salon owner checking online bookings on a laptop.”
Avoid: “SEO best salon marketing cheap SEO UK.”

Describe what the image communicates. Upload a sensibly sized file, not an enormous original. The website handles responsive image delivery.

Links

Select meaningful words, then choose the link tool. Internal links can use /contact or /web-design. External links should use a full https:// address.

Open in a new tab and Mark as nofollow are available. Use them intentionally; do not mark every internal link as nofollow.

Body formatting

Use Paragraph, Heading 2–4, Quote, bullet/numbered lists, bold and italic. Add images where they help explain the article.

Paste text, then review its formatting. WordPress shortcodes, Elementor layouts, embedded scripts and arbitrary HTML are not supported article blocks here.

09 / GOING LIVE

Understand the three different clocks.

1

Sanity draft

Your edits save while you work. They are not public just because they are saved. Click Publish when approved.

2

Website refresh

With the publish webhook enabled, publishing requests a website refresh. It may take a little time. If the webhook is off, the normal fallback cache interval is one hour, with regeneration on a later visit.

3

Google recrawl

Google updates its own index separately. A website change appearing live does not mean Google’s search result has already changed.

Check the result in this order

  1. Check Sanity.

    Make sure publication completed and you are not looking at unpublished changes or unresolved errors.

  2. Check the actual website.

    Open the correct URL in a new tab. For a new post, check both /blog and /blog/your-slug. Inspect the mobile layout too.

  3. Check metadata when you changed SEO fields.

    Use your normal browser SEO inspection tool, or View Page Source and find the title, meta description and canonical. Confirm noindex is absent for a page intended for search. Browser tools may display titles with a site-name suffix.

  4. Check Search Console if appropriate.

    Use URL Inspection for the exact canonical URL. Submit the sitemap if it has not been submitted: www.truedgedigital.co.uk/sitemap.xml. You do not need to manually add each post to this sitemap.

If you cannot see your edit

Do not repeatedly change fields to force an update. Check Publish, the URL and the publication date first. Ask the technical team to check the webhook/cache if the live site is still stale.

For this integration, the team must enable the existing publish webhook after deploying the website. Until that setup is complete, allow for the cache fallback rather than expecting immediate updates.

11 / WHEN SOMETHING LOOKS WRONG

A quick answer before you get stuck.

I signed in, but cannot see the project.

Check that you used the email/account invited to Truedge’s Sanity project. Ask the project owner to invite you and give the appropriate editor role. Do not create a new Sanity project.

Publish is blocked or there is a red message.

Open the indicated field and complete it. New posts need a title, valid slug, publication date, excerpt, featured image with image description, and a body. A reference to an unpublished author/category may also need attention. If your role cannot publish, ask the project owner.

My post is published, but it is not on /blog.

Check its publication date is not in the future, the slug exists, and publication actually completed. Then allow for the website refresh. If these are correct, send the technical team the post title, URL and time you published.

I changed the SEO title, but the big heading did not change.

That is expected. Edit Page heading (H1) in a page’s Content tab, or Post title (H1) in a post’s Post content tab, when you want to change the visible heading.

I changed the description, but Google still shows the old one.

First check the live page metadata. Google recrawls separately and may choose another snippet even after recrawling. Do not keep rewriting a correct field just because the search result has not changed yet.

The image looks cropped, or social sharing shows an old image.

For featured images, review the crop/hotspot where available and check the live layout. For shared-link images, use the SEO social image field; social platforms may cache an older preview. Changing the social image does not change the article’s featured image.

I made a mistake. How do I undo it?

For unpublished edits, use the document’s actions menu to discard draft changes if available; that discards all pending draft edits, not just one field. For a published mistake, correct the field and Publish again. Use document history if your permissions/plan provide it, or ask the team before restoring an older version.

Should I unpublish or delete an old post?

Discuss it with the team first: removing a published post can leave a broken URL and may need a redirect. “Hide from Google” keeps the post accessible and in the blog list; it is not the same as unpublishing. Never delete a referenced image without checking where it is used.

12 / WHO DOES WHAT

You own the content. The team owns the code.

You can do this in Sanity

  • Edit existing page H1s, introductions, metadata and FAQs.
  • Create, update and publish complete blog articles.
  • Add article images, alt text, links, authors and categories.
  • Set per-page/post social images and reviewed SEO options.

Ask the technical team for this

  • Create a new main website page or an author archive. Category archives are automatic.
  • Change layouts, colours, navigation, pricing cards or other page sections outside the exposed fields.
  • Add redirects after a URL change.
  • Change analytics, Search Console verification, plugins, robots rules or sitemap logic.
  • Resolve access, webhook, domain or deployment problems.
Your first task, kept simple

Open one existing page → review SEO settings → make one approved improvement → Publish → verify the live URL. Once that feels familiar, create a blog draft and work through the post checklist.

When asking for help, include: the page/post name, its URL, what you changed, when you published, and what you expected to see. A screenshot of the error is useful. Never send passwords or authentication tokens.
